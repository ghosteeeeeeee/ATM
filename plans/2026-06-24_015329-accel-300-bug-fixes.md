### Task 5 — Item 5: SHORT confidence gap-growth bonus (P1)

**File:** `/root/.hermes/scripts/signals/accel_300.py`
**Line:** 716

OLD:
```python
        gap_bonus = max(0, sig['gap_growth'] - 0.05) * 200  # max ~20 for 0.15%+ growth
```

NEW:
```python
        # Use abs(gap_growth) so SHORT signals (where gap_growth is negative) can
        # earn the bonus just like LONG signals. Threshold = 0.05% matches LONG;
        # SHORT's gate is stricter (0.07%) so any SHORT that earns this bonus is
        # meaningfully stronger than the LONG equivalent.
        gap_bonus = max(0, abs(sig['gap_growth']) - 0.05) * 200  # max ~20 for 0.15%+ growth
```

**Why not use `ACCEL_300_MIN_GAP_GROWTH_SHORT = 0.07` as the threshold?** Because that would require SHORT gap_growth to exceed 0.07% to earn any bonus, which is harder than the LONG path's 0.05%. The original LONG threshold of 0.05% applies to LONG; using `abs()` keeps the threshold symmetric without favoring either side. If T wants asymmetric thresholds (SHORT requires 0.07% to earn bonus), that's a separate decision — flag for follow-up.

**Verification:**
- After the fix, query the signals DB for SHORT signals with `value < -0.07` (which clear the SHORT gate at line 384): `sqlite3 /root/.hermes/data/signals_hermes_runtime.db "SELECT id, value, confidence FROM signals WHERE signal_type='accel_300_short' AND value < -0.10 ORDER BY id DESC LIMIT 10;"` — confidence should now be higher than 70 for SHORT signals with large negative value (gap_growth).
