# accel-300 EMA Calculation Fix (2026-05-14)

## Problem
Custom `_ema_series()` used SMA of first 300 prices as seed, then EMA recurrence. Pandas `ewm(span=300, adjust=False)` uses first price as seed. The seeds differ by ~420 on BTC, creating ~0.44 absolute difference in EMA values and ~0.0005% gap error — small but the code wasn't using the standard.

## Root Cause
Custom EMA seeded with `sum(values[:period]) / period` (SMA) at index 299. Pandas seeds with `values[0]` (first price). The code intended true EMA but used SMA initialization.

## Fix Applied
Replaced custom EMA with pandas `pd.Series.ewm(span=period, adjust=False).mean()`:

```python
def _ema_series(values: list, period: int) -> list:
    """Return EMA series (oldest first), None for indices < period-1."""
    import pandas as pd
    if len(values) < period:
        return [None] * len(values)
    s = pd.Series(values)
    ema = s.ewm(span=period, adjust=False).mean().tolist()
    # pd.ewm computes from start; override first (period-1) with None
    for i in range(period - 1):
        ema[i] = None
    return ema
```

Key: `adjust=False` = pure recursive EMA (no weighted average over lookback). `span=300` = α = 2/(300+1). Pandas computes from start; first `period-1` values are valid but should be `None` per signal convention — override those with `None`.
