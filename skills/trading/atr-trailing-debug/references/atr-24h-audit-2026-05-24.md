## Why ATR SL Loses on Every Trade

### 1. Phase k-scaling is broken in practice

```python
# position_manager.py line 1576:
ms = get_momentum_stats(token)
momentum_by_token[token] = ms  # or None if failed

# tpsl_utils.py line 108:
if momentum_stats is None:
    return base_k  # NO phase tightening when momentum_stats is None!
```

Every signal in SQLite signals table: `momentum_state=null, rsi_14=null, macd_hist=null`.
When `get_momentum_stats()` returns None → phase multipliers bypassed → base_k used → SL is a fixed % from anchor with no tightening.

### 2. Floor overrides phase multipliers in almost every case

For a coin with atr_pct=1.5% and k=1.0:
- Raw sl_pct = 1.5%
- MIN_SL_PCT = ATR_SL_MIN_INIT = 1.0% (or ATR_SL_MIN_ACCEL = 1.0%)
- Floor caps at 1.0%
- Phase multipliers (0.01-0.07) would tighten further but floor overrides whenever k×atr×mult < MIN

### 3. Highest/lowest price may not be updating

Trailing SL tightens by computing from `highest_price` (LONG) or `lowest_price` (SHORT).
If these aren't being updated by position_manager each cycle, the anchor stays at entry → SL never moves.

### 4. 15 losing trades had SL placed inside entry

For a LONG trade: `(stop_loss - entry_price) / entry_price < 0` means stop is BELOW entry.
Price only needs to reverse by 0.001% to hit SL. These coins dropped immediately after entry.

## ATR Formula — Verified Correct

Both directions confirmed by independent subagent (2026-05-24):

```
LONG:  SL = anchor × (1 - sl_pct)    TP = anchor × (1 + tp_pct)
SHORT: SL = anchor × (1 + sl_pct)    TP = anchor × (1 - tp_pct)
```

Phase multipliers are tighter than old docs said:
- ACCEL_STALL = 0.06 (not 0.05), ACCEL_FAST = 0.07 (not 0.25)
- INIT vs ACCEL floors are EQUAL (both use 1.0% SL, 1.5% TP)
- ATR_PCT_HIGH_THRESH boundary: `1.5% > 1.5%` = False → falls into NORMAL tier
