## Findings

**F-1 (MED, pre-existing open-path) — no fill-vs-target validation when a pending order fires; no TP-side analogue of SL-FIX.**
Shape sanity validates `target < trigger < sl` against the **trigger only** (`trade_watchdog.py:1417-1422`), never against the FILL. If price gaps trigger→target during fire latency (armed target distances measured: **0.67–1.63%**; monitor cadence 1-min), the market fill lands below target (short) → wrong-side TP born on an `ai-trader-pending` trade. `brain.py add_trade` (:332, :786) performs **zero** target-side validation; `decider_run.py:6639-6678` has an **SL-FIX** for wrong-side stops at open but **no TP-FIX exists anywhere** (grep clean). Consequence: next ≤1-min hit-check fires `manual_tp_hit` while price sits in `(entry, target]` → loss bounded by the gap (0.7–1.6% raw ≈ 3.4–8% leveraged at 5×). Not introduced by this fix (R2 scope was UPDATEs), but it is a path that **can** place a loss-side TP on an ai-trader-* trade — graded MED not HIGH because it requires a full-target-distance gap in the fill window (flash-crash only), the loss needs a bounce back into the band, and the routine wrong-side class (R2) is fully closed.

**F-2 (MED, HEAD) — seed-only birth does not keep the armed stop "never overridden"; it is re-anchored (and can be LOOSENED) at the first 15m structure change.**
Docstring `auto_trader.py:343` "Birth = SEED ONLY — the armed/ATR stop the trade arrived with stands (never overridden)" and the v3 commit message "armed stop now survives forever" overstate the behavior: seed-only protects **birth only**. Live evidence — **#16882** (opened 14:45, `btc-ceo-short-71700` ladder rung): stop held at armed **71950** at seed ✓, then first structure change at **15:19 bumped it to 72490** = **+540pts, risk 0.44%→1.19% of entry**, then 15:49 → 72327. This is the *same* +659pt loosening pattern the v3 message calls "needless risk" for #16879 — deferred from birth to first structure change, not eliminated. `_lag_stop` has **no improve-only ratchet** (contrast mxm's CEO-stop protection `manual_exit_manager.py:240-251`, which stands down on `dynamic_sl:false` so it can't help here); only F-3 (no un-breach), F-4 (±5% price cap), F-5 (side-specific) bound it. Also: armed stops that are **not** zigzag-structure-based (round numbers `btc-ceo-short-71700`, `-73500`, flagfloor) are silently replaced by 15m zigzag structure at first change. Per the CEO's own lag rule ("bump to now-old structure") this is spec-compliant — flagging so the CEO decides whether "never override the armed stop" was meant literally (→ needs an armed-stop ratchet) or whether alignment-at-first-change is accepted. *The hypothesized opposite gap ("far-from-structure stop never aligned") does not exist — H6.*

**F-3 (LOW) — `manual_tp_hit` label has no fill-vs-entry sanity guard (asymmetric with the SL label).**
`position_manager.py:572-576` relabels `atr_tp_hit → manual_tp_hit` on price-vs-target alone; the SL branch **does** compare against entry (:582-585 `_profit_side`), the TP branch does not. Paper path is safe by construction (exit = detection price ≤ target ≤ entry×0.999). Live path records the **actual fill** (#16878: target 72796.9, recorded exit 72823 = 26pts worse). Worst observed BTC adverse fill = **0.036%** vs 0.1% guard = 2.8× headroom — but 15m avg range 0.304% means a detect→fill V-reversal in the giant-candle scenario the TP exists for can exceed it → label can still lie. Also: guardian hard_tp buffer `_margin=0.001` applies only when `atr_managed` (`hl-sync-guardian.py:2066-2075`); ai-trader trades are `atr_managed=False` (#16882 row) → **zero buffer** on that path. At HEAD the armed margins (0.67–1.63%) make it 19–45× worst-observed → effectively safe. *Recommendation (not applied):* relabel/guard at close — if exit is on the wrong side of entry, don't call it `manual_tp_hit`.

**F-4 (LOW, bcc7b3f6 only, moot at HEAD) — 0.1% guard boundary is net-breakeven after fees.**
Guard is inclusive at exactly `entry*0.999` (A5). Gross 0.100% − round-trip taker 0.090% (`TAKER_FEE=0.00045`/side) = **+0.010% raw = $0.0056 on $11.10@5x** — a boundary snap is economically a **"breakeven TP"**, the exact complaint class. Mitigating: all 6 historical legit snaps landed **0.1396–0.686%** (min #16834 0.1396% → net +$0.028), so typical structure spacing clears fees; the boundary band (0.10–0.14%) is rare. If R2 is ever reinstated, use **≥0.15%** (fees + slippage buffer). At HEAD moot — R2 removed.

**F-5 (LOW, HEAD) — 15m source multiplies stop-churn 3.5× with a 45% loosening share and no hysteresis.**
Quantified (H5): sh changes on **81% of 30-min watchdog cycles** (390/481 over 10d; ~39 bump-triggers/day) vs 23% for 1h (~11/day); avg step 147pts; **45% of changes RAISE sh** = loosen a short's stop; the 200-candle/50h window slides ~4× faster than the 1h/150-candle window, so swings aging out of the window change `sh` without any new formation (prior F-10, now at 15m rate) — included in the 81%. In chop the stop therefore re-anchors nearly every cycle, alternating tighten/loosen, bounded only by F-3/F-4/F-5 and ±5% cap — **no direction ratchet** (see F-2). This is CEO-mandated ("1h too slow, zero trailing") so behavior is intended; flagging the frequency/loosen-share for monitoring. Note `TF_LIMIT['15m']=200` (`structure_analysis.py:31`), not 150.

**F-6 (LOW) — top-level non-dict state JSON still aborts the whole tweak loop (F-1 fixed per-entry only).**
A valid-JSON-but-wrong-type state file (list) makes `_smap.get(key)` raise `AttributeError` at `auto_trader.py:406` **before** the F-1 isinstance check → propagates out of `tweak_structure_fixed` → caught only as `WARN tweak_structure_fixed failed` (:562) → **R1+R2 dead for ALL positions that cycle**, and no save-on-exception means the corrupt file persists. Load-time try (:396-400) catches unparseable JSON but not wrong type. Trigger = manual file corruption only (both writers always dump dicts). Harness B2c still detects it.

**F-7 (LOW) — ATR-engine TP first-set has no entry-side guard; `MANAGED_TAGS` gap makes `ai-trader+/-` reachable.**
`tpsl_utils.py:890/903` first-set TP has no entry comparison (the WRONG-SIDE SAFETY NET at :656 covers **SL only**). `_collect_atr_updates` skips only `MANAGED_TAGS = ('ai-trader-manual','ai-trader-pending','ai-trader-auto')` (`manual_exit_manager.py:67`, skip at `position_manager.py:2152`) — **`ai-trader+`, `ai-trader-`, `ai-trader` are not skipped**, so `_persist_atr_levels` (`position_manager.py:2453`) can write their target. Loss-side placement is **provably blocked in practice** by three incidental guards: (a) tighten-only TP gate (`tpsl_utils.py:893-901`) — any computed value above the existing correct-side target is refused; (b) peaks seeded at entry (`brain.py:805-806`) → ref ≤ entry for shorts → first-set also profit-side; (c) target always set at open (0 open trades missing target; last `ai-trader+` closed 2026-10-19). Graded LOW not HIGH: path exists (would be HIGH by the "any other UPDATE" rubric) but loss-side write is unreachable under every current invariant — and the guards are incidental, not explicit. *Recommendation:* add an entry-side check to the TP first-set (mirror of this fix) and/or add `ai-trader+/-` to the skip list if rr_engine owns their exits.
