## The 8 items

**1. Skill not in the agent's catalog.** `skill(name="ceo-comm")` returned "unknown or no
longer available"; the agent had to `cat` SKILL.md via bash. Priority 1 per the tester.
- *My verification:* the symlink `skills/shared/ceo-comm -> /root/.config/opencode/skills/
  ceo-comm` is valid; SKILL.md is readable through it; frontmatter parses cleanly. All 52
  shared skills have a SKILL.md, and control skills (bug-hunter, signal-lab, decisions) are
  structurally identical. Description is 310 chars — comparable to signal-lab (322) which
  DOES resolve. The declared triggers include the exact phrase the agent used ("strategic
  review"). So this is NOT a missing-file or malformed-frontmatter defect.
- *Question:* what is the actual resolution mechanism, and what do we change? Options: rename
  to a more literal trigger, add a `skills.json`/index if one is expected, or accept that
  DSH's catalog is built at startup and a restart is required. Do we know?

**2. Dead-pattern stub.** The agent used `cat ceo_prompt.md | opencode run --port 4099`
early in the session, before the stub existed. It endorses the fail-loud stub design
unreservedly and says it would have repeated the mistake on its next turn without it.
- *Question:* any change needed, or is this closed?

**3. Exit-0 trap cost it once.** Its first deep run died at 2 tool calls on a sandbox
permission rejection; the detached wrapper still returned 0, so it looked like success. It
caught it only by reading the jsonl. The `.exit` class mechanism would have flagged it.
- *My verification:* the mechanism is real — `ceo_classify_run` writes a CLASS plus rc to
  `.exit` for every runner, and history shows real samples (`ok rc=0`, `failed rc=0`,
  `incomplete rc=124`). It predates this tester's run, so the tester hit it BEFORE the fix
  landed, or did not know to read `.exit`.
- *Question:* is the remaining gap documentation-only (callers must be told `.exit` exists),
  or should the runners print the class to STDOUT on completion so nobody has to know?

**4. The `/tmp` ban is at the wrong layer — HIGHEST SEVERITY.** The tester's real killer
was a rejected TOOL CALL: the agent tried to `cat` the session-lock file mid-run and the
whole call was rejected. Banning `/tmp` *briefs* (exit 4) is good but does not address this.
It asks us to extend path policy to block the AGENT from touching temp paths mid-session.
- *My verification — and this is worse than the tester knew:* there is NO enforcement. Only
  an instruction in the deep prompt. Worse, my own earlier config change
  (`permission.external_directory` allowing `/tmp/*` and `/var/tmp/*`) means a mid-run temp
  read is now explicitly ALLOWED, not rejected. And `run_ceo_deep.sh:155` still carries the
  STALE claim that "opencode auto-rejects /tmp/* access and a single /tmp read will kill
  this session" — which my config change made false. So today: the guard is gone, the
  instruction is stale, and the lock file is readable by any CEO agent.
- *Question:* this is a real regression I introduced. Rule on the correct end-state:
  (a) revert the config allow and go back to instruction-only (sessions die again),
  (b) keep the allow but move the lock file OUT of the temp dir into the workspace so it is
  not external at all, (c) narrow the config allow and add an explicit deny for the lock
  path, or (d) something else. Recommend the exact change.

**5. Budget tight for decision-heavy briefs.** 33 tool calls then `incomplete rc=124` at
1800s. Checkpoint-first saved it. The tester's read: a research-heavy consult genuinely
needs the full budget.
- *My verification:* this matches the one real budget exhaustion on record (192508Z, 1617s
  spent investigating, never dispatched). The tester is describing the same failure.
- *Question:* raise the budget, or split deep into decide + separately-budgeted dispatch?
  This has been logged open twice already. Settle it.

**6. `--wait` cuts the budget exactly when you want to watch.** Foreground drops 1800s to
600s. The tester calls this "backwards" — it wanted to sit and watch a run that needed
~1700s, and 600s would have killed it. Asks for 1800s under `--wait`, or a separate flag.
- *My verification:* `run_ceo_deep.sh:71-72` — `BUDGET=1800` then `[ "$WAIT" -eq 1 ] &&
  BUDGET=600`. Real. Note the tension: I shipped 600s deliberately, reasoning that a
  foreground run blocks the caller's turn. The tester's use case (watch a long run) is
  exactly what detached + tail is for. Argue both sides and rule.

**7. Raw `--format json` floods stdout for in-process runs.** Consult/status stream jsonl
events; the actual answer is buried and had to be grepped out of the jsonl.
- *My verification:* `run_ceo.sh:95` and `run_ceo_consult.sh:103` both emit `--format json`
  to stdout. Real. The detached runners redirect to a file, so this is in-process-only.
- *Question:* add a `--quiet`/progress mode, or post-process to print only the final text?

**8. Consult opinions are not persisted.** Correctly read-only, so the ruling exists only on

- *My verification:* confirm consult writes nothing today (no lock, no report write). The
  proposal preserves that invariant while making rulings durable.
- *Question:* approve `--save` to a separate dir? What retention?
